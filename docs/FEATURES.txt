컴패니언 프로토타입 0.8 (신경망이 조종하는 아바타)

실행
1. 처음 한 번: install.bat을 더블클릭하세요(아래 "다른 컴퓨터에 설치하기" 참고). 직접 하려면 같은 작업을 이렇게 해요.
   py -m pip install -r requirements.txt   (edge-tts 음성과 Word/PowerPoint/Excel 문서용)
2. start.bat(또는 start-desktop.bat)을 실행하세요. 콘솔에 키를 입력할 필요는 없어요. AI는
   설정에서 고르고(아래 "AI 모델" 참고), 예전 환경 변수 ZAI_API_KEY가 설정돼 있으면 한 번 가져와요.
3. 브라우저가 열려요(마이크를 쓰려면 Chrome이나 Edge가 좋아요).
4. 검은 창은 닫지 마세요. Ctrl+C로 앱을 종료해요.

AI 모델 (설정 → "루나가 사용할 AI")
- 드롭다운 목록: Z.ai (GLM), OpenAI, Anthropic (Claude), Google Gemini, OpenRouter(온라인, 키 필요)와
  이 컴퓨터에서 도는 로컬 프로그램인 Ollama, LM Studio, Jan, llama.cpp server가 있어요.
- 키가 없는 온라인 서비스를 고르면 입력 창이 나타나요. 키는 서비스에서 확인하고, "취소"를 누르면 아무것도 바뀌지 않아요.
  올바른 키는 저장되어 다음부터는 저절로 연결돼요. "키 변경"과 "키 삭제" 버튼이 있어요.
- 키는 Windows 기능(DPAPI)으로 암호화해서 keys.dat에 저장해요. 이 컴퓨터의 이 Windows 사용자만 복호화할 수 있어요.
  페이지는 키를 다시 받는 일이 절대 없고(마지막 4자리만 보여요), 로그나 오류 메시지에도 키가 나오지 않아요.
  keys.dat와 providers.json은 .gitignore에 들어 있어서 공개 저장소에 올라가지 않아요.
- 로컬 AI 찾기: 시작할 때와 "로컬 AI 찾기" 버튼을 누를 때 프로그램들의 포트와 설치 폴더를 확인해요.
  실행 중인 것을 찾으면 루나가 연결할지 물어봐요. "나중에"를 고르면 기억해요. 설치만 되어 있고
  실행 중이 아니면 먼저 실행해야 한다고 알려 줘요.
- 연결한 뒤에는 드롭다운에서 모델을 골라요(온라인 서비스는 서비스에서 목록을 받아 와요). 화면이나 카메라를 보려면
  이미지를 인식하는 모델을 골라요. Z.ai는 glm-4.6v-flash, 로컬은 llava/gemma3/qwen-vl 등이에요.
  그런 모델이 없으면 루나가 솔직하게 말해 줘요.
- 선택한 AI, 모델, 화면 언어는 저장돼요. 라벨과 오류 메시지는 en/ru/ko/ja로 준비돼 있어요.
- 개인정보: 온라인 서비스를 쓰면 메시지(허용했다면 이미지도)가 그 서비스로 가요. 로컬 AI를 쓰면 edge-tts 음성을 빼고는
  아무것도 컴퓨터 밖으로 나가지 않아요.

문서: WORD, POWERPOINT, EXCEL
- 이렇게 부탁해 보세요. "составь отчёт", "сделай презентацию про…", "таблицу расходов с итогом и диаграммой". 루나는 필요하면
  먼저 누구를 위한 어떤 내용인지 묻고, 문서를 준비한 다음 "문서를 만들까요…?" 카드를 보여 줘요
  ("만들고 열기" / "만들기"). 누르기 전에는 파일이 없어요. "동작"의 첫 번째 스위치(사이트와 프로그램 열기)가 켜져 있을 때 작동해요.
- 파일은 문서\Luna 폴더에만 만들어지고, 이미 있는 파일은 절대 덮어쓰지 않아요("(2)"가 붙어요).
  고치고 싶으면 무엇을 바꿀지 말해 주세요. 문서를 다시 만들어서 새 사본으로 저장해요.
- 작동 원리: 루나는 파일을 쓰지도 코드를 쓰지도 않아요. 문서를 짧은 JSON으로 설명할 뿐이에요(제목, 문단,
  목록, 표 / 항목과 메모가 있는 슬라이드 / 수식과 차트가 있는 시트). office.py가 모든 필드를
  엄격한 한도로 검사한 뒤 파일을 만들어요(python-docx, python-pptx, openpyxl). Excel에서는 해가 없는 수식만 허용돼요
  (SUM, AVERAGE, MIN, MAX, COUNT, ROUND, IF 등). HYPERLINK나 다른 통합 문서 참조 같은 나머지는
  그냥 글자로 남아요. 루나가 스스로 파일을 만드는 일은 없고, 사용자의 요청에 대한 답으로만 만들어요.
- 성격: 문서 자체는 깔끔하고 사무적이지만 루나는 루나 그대로예요. 가까운 사람처럼 물어보고, 함께 기뻐하고,
  고쳐 보자고 제안하고, 사용자가 지친 것도 알아채요. 이건 템플릿이 아니라 루나의 지침에 들어 있어요.

다른 컴퓨터에 설치하기
- 프로젝트 폴더를 통째로(아바타 모델이 있는 assets\models도 함께) 복사하고 install.bat을 더블클릭하세요.
  Python을 알아서 찾거나(winget으로) 설치하고, requirements.txt의 라이브러리, 데스크톱 창용 Node.js와 Electron을 설치한 뒤
  프로젝트 파일과 아바타 라이브러리의 인터넷 접근을 확인해요. Ollama(로컬 AI)는 설치하지 않아요.
  로컬 AI를 쓰려면 ollama.com에서 직접 설치하세요. 앱이 실행 중인 서버를 보고 찾아내요. 이미 설치된 것은
  건드리지 않아서 다시 실행해도 안전해요. "install.bat --check"는 확인만 하고 아무것도 바꾸지 않아요. 메시지 언어(English,
  Русский, 한국어, 日本語)는 Windows 언어를 따르고, "install.bat --lang ko"로 직접 정할 수 있어요.
- Windows가 "허용하시겠습니까?"라고 물으면 "예"를 누르세요. Python이나 Node.js를 설치한 뒤 창에서 찾을 수 없다고 나오면
  창을 닫고 install.bat을 다시 실행하세요.
- 설치 프로그램은 사용자의 데이터를 건드리지 않아요. 다른 사람에게 복사하면 안 되는 것: keys.dat(키는 내 Windows
  계정에 묶여 있어서 다른 컴퓨터에서는 어차피 열리지 않아요), providers.json, memory.json(루나가 나에 대해 기억하는 것이라
  다른 사람은 깨끗하게 시작하는 편이 좋아요), journal.jsonl, ui-state.json, edit_backups, desktop\node_modules, __pycache__.
- 설치에 새 항목을 추가하는 방법: Python 라이브러리는 requirements.txt에 한 줄, npm 패키지는 desktop\package.json에, 프로그램은
  tools\install.py의 PROGRAMS에 한 줄(winget용 id), 필수 파일은 FILES에, 페이지가 불러오는 인터넷 주소는 ONLINE에 추가해요.
  읽고 고쳐야 하는 파일은 tools\install.py뿐이고(메시지 텍스트: TEXT 사전, 언어마다 키 하나씩), install.bat은 건드릴 필요가 없어요.

루나의 성격과 기억: 별도 모듈
- 루나를 "루나답게" 만드는 모든 것(나에 대한 장기 기억, 루나 자신의 생각, 기분, 개인 일기, 호기심과
  한가한 시간의 독서, "누구이고 무엇을 기억하는지"에 관한 지침의 일부)이 character.py 파일 하나에 있어요. 이 파일은 페이지, 음성,
  아바타, 컴퓨터, 선택한 AI에 대해 아무것도 몰라요. 프로그램의 주인이 "두뇌"를 한 번 연결하고
  (character.llm = 메시지를 받아 텍스트를 돌려주는 함수) 모듈의 함수를 호출해요. 같은 성격과 같은
  기억(memory.json)을 다른 프로그램(게임, 봇, 다른 인터페이스)에 연결할 수도 있어요.
- app.py는 이제 주인 역할만 해요. 서버, 음성, 손(열기, 마우스, Unreal, 문서, 코드), AI, 상황(시간대,
  배경, 언어)이에요. 지침 텍스트는 옮긴 뒤에도 바이트 단위로 똑같아요(비교로 확인했어요).
- 이 모듈은 사이트를 띄우거나 네트워크 없이 따로 테스트할 수 있어요.

날짜, 약속, 습관, 배려
- 루나는 몇 마디에 한 번씩 평소 기억과 함께 중요한 것을 골라내요. 날짜(시험, 마감, 생일),
  약속(사용자의 것과 루나의 것), 습관(예: "자주 아침까지 깨어 있어요")이에요. memory.json(moments 목록, 최대 20개)에 저장되고,
  알맞은 때 루나의 지침에 들어가요. 2주보다 먼 날짜는 지침에 넣지 않고, 3일 넘게 지난 날짜는 잊어요.
- 루나가 먼저 하는 배려는 시작할 때의 인사에서만, 한 번에 한 가지만 해요. "내일 시험이네요",
  "어제 늦게까지 안 잤는데 괜찮아요?"(새벽 5시 전까지 루나에게 글을 썼고 지금이 아침이나 낮이라면), "약속한 건 어떻게 됐어요?"
  같은 말이에요. 같은 날짜는 12시간에 한 번보다 자주 말하지 않고 평생 세 번까지만 말하며, 습관은
  절대 상기시키지 않아요. 이건 배려이지 일정 관리자가 아니니까요.
- 시간에 맞춘 깨우기: 루나가 실행 중이면(트레이에 숨어 있어도) 2분마다 페이지가 서버에 오늘이나 내일의 날짜를
  말할 때가 됐는지 물어봐요. 오전 9시부터 오후 9시까지만이고, 밤에는 절대 안 해요. 때가 되면 창이
  트레이에서 돌아오고 루나가 한마디를 해요. 스위치는 루나가 먼저 말 거는 기능과 같아요("루나가 먼저 말 걸기").
- 캘린더와 메일은 연결되어 있지 않아요. 내 계정에 OAuth로 로그인해야 하는데, 그건 보안에 관한 별도의 결정이에요.
  루나는 사용자와의 대화로만 날짜를 알아요.

음성과 억양 (voice.py)
- 음성은 edge-tts가 만들어요. 속도, 높이, 볼륨만 바꿀 수 있고 "감정 스타일"이나 진짜 웃음은 없어요.
  그래서 억양은 가진 것들을 조합해서 만들고, 다음에 따라 달라져요.
  1) 답변 안의 감정 태그([happy], [sad], [angry], [giggle] 등): 태그마다 속도, 높이, 볼륨이 달라요.
  2) 루나의 기분(memory.json의 기쁨과 활기): 즐거울 때는 조금 높고 빠르게, 슬플 때는 낮고 느리게 말해요.
  3) 시간대: 깊은 밤(23시부터 6시)에는 더 조용하고 느리게 말해요.
  4) 문장 부호: "!"는 생기를 주고, "?"는 끝을 올리고, "..."는 느려지며 잦아들어요.
  5) 소리로 쓴 웃음과 한숨: "Ха-ха-ха", "хихи", "Эх...", "Ох..."(쓰는 법은 지침에 설명돼 있어요). 웃음은 쉼표로 나뉘어 따로따로 "터져요".
  6) 페이지에서 정한 음성 설정(속도와 높이): 모두 이것과 합쳐지고 안전한 범위로 제한돼요.
- 솔직히 말하면, 여기서 웃음은 텍스트에 바뀐 톤을 더한 것이지 녹음된 웃음이 아니에요. 어떻게 들리는지는 귀로 들어 봐야 해요. 이 수정을 한 저는
  확인할 수 없었어요. 진짜 감정을 원하면 다른 음성 엔진이 필요해요(아래 "앞으로" 참고).

루나는 하녀가 아니라 하나의 인격이에요
- 루나는 동의하지 않을 수도 있고, (차분하게 근거를 들어) 논쟁하고, 조언하고, 서운해하고, 진심으로 고마워할 수 있어요. 하지만 늘
  따뜻해요. 서운함이 냉담함이 되지 않고, 논쟁이 무례함이 되지 않아요.
- 루나는 글로 사용자의 어조를 읽어요(러시아어와 영어). 무례함, 화, 슬픔, 피곤함, 기쁨, 고마움,
  사과를 알아봐요. 슬플 때는 고치려 하지 않고 먼저 곁에 있어 줘요. 피곤할 때는 더 부드럽고 짧게 답해요. 무례하면
  서운해하고, 그 기분은 최대 세 시간 남아요. 사과하면 서운함이 풀리고 루나의 마음이 따뜻해져요.
- 어조는 신경망 없이 단어와 기호(예: 대문자, "!!!")로 판단해요. 거칠지만 예측 가능하고 무료인 평가예요.
  목소리의 억양을 소리로 듣지는 못해요.

컴퓨터에서 보는 것: 영화, 애니, 영상, 음악 (media.py)
- 설정(Electron 창에서만)에 "보거나 듣는 것 알아채기" 스위치가 있어요. 실행할 때마다
  꺼져 있고, 사용자가 확인한 뒤에만 켜져요. "루나가 먼저 말 걸기"도 켜져 있어야 해요.
- 활성 창의 제목만, 15초에 한 번 읽어요. 이미지도 소리도 저장하지 않아요. 제목이 플레이어나 온라인 극장
  (YouTube, Crunchyroll, Netflix, Kinopoisk, VLC, Spotify 등)처럼 보일 때만 AI로 보내요.
  메일, 문서, 채팅은 절대 보내지 않아요.
- 같은 제목이 화면에 40초 이상 있고 사용자가 루나와 말하고 있지 않으면, 한두 마디를 할 수 있어요.
  어떻게 생각하는지, 뭐가 좋은지, 뭐가 재밌거나 아쉬운지요. 8분에 한 번보다 자주 말하지 않고, 같은 제목은 12분에 한 번보다
  자주 말하지 않으며, 세 번까지만 말해요. 잠자코 있을 수도 있어요. "как тебе это?"라고 물으면 무엇이 열려 있는지 알고 있어요.
- 루나가 "작품을 아는" 정도는 선택한 AI가 아는 만큼이에요. 모르면 솔직히 말하고
  물어봐요. 줄거리나 사실을 지어내는 건 금지돼 있어요. 영화, 애니, 음악, 게임에 대한 의견은 기억에 저장해요.
- 이 스위치 자체는 소리를 듣지 않고 제목만 읽어요. 창 제목을 보고 힌트를 얻는 거예요. 소리는 별도의 "청각"(아래)이 들어요.

ELECTRON 창에서의 음성 입력(마이크)
- Electron 안에서는 브라우저에 내장된 음성 인식이 작동하지 않아요(오류 "Микрофона: network"). Google의 인터넷 서비스가 필요한데
  Electron 창에서는 쓸 수 없거든요. 그래서 데스크톱 창에서는 서버가 직접 마이크를 듣고 이 컴퓨터에서
  음성을 인식해요(Vosk). 인터넷은 필요 없고, 소리는 저장되지 않아요. soundcard와 vosk 패키지는 install.bat이 설치해요(또는
  py -m pip install soundcard vosk). 처음에는 작은 음성 모델(약 45MB, Vosk 공식 사이트)을 내려받아요.
- 러시아어와 영어를 알아들어요(설정의 "음성 인식 언어"에서 선택). 일반 브라우저(Chrome, Edge)에서는 예전처럼 브라우저에 내장된
  음성 인식을 써요.
- 말하는 도중에 인식해요. 말하는 동안 입력란에 단어가 나타나고, 말이 끝나면 바로 문장이 전송돼요(문장의 끝은
  인식 자체가 판단해요). 한 문장은 최대 14초이고, 7초 동안 아무 말도 없으면 그냥 꺼져요.
- 한국어와 일본어: sherpa-onnx 패키지가 설치되어 있으면(py -m pip install sherpa-onnx sounddevice) SenseVoice 모델로 인식해요
  (약 160MB, GitHub k2-fsa에서 한 번 받아 models 폴더에 저장해요). Vosk보다 훨씬 정확하지만 느린 프로세서에서는 문장이
  말하는 도중이 아니라 멈춘 뒤에 인식돼요. 마이크는 sounddevice로 읽고(소리 손실 없음), 없으면 soundcard로 읽어요.
- 조용한 마이크: 음성 볼륨을 자동으로 끌어올려요(그렇게 하지 않으면 Vosk는 조용한 마이크에서 아무것도 듣지 못해요). 방의
  소음은 말로 바뀌지 않아요.
- 정확도: 작은 Vosk 모델은 단어를 몇 개 틀려요. 그래서 마이크로는(sherpa-onnx가 설치되어 있으면) 러시아어를
  GigaAM 모델로 인식해요(약 170MB, GitHub k2-fsa에서 한 번 받아 models/sherpa 폴더에 저장해요. 제가 넣어 두었다면
  이미 거기 있어요). Vosk보다 훨씬 정확하지만 문장이 멈춘 뒤에 나타나고(느린 프로세서에서는 문장 길이 정도 걸려요),
  말하는 동안에는 Vosk의 거친 단어가 보여요. GigaAM을 불러오는 동안(시작 후 약 10초)이나 없을 때는
  예전처럼 Vosk가 들어요. 스피커 소리("청각")는 지금도 Vosk가 인식해요.
  마이크의 영어는 한국어, 일본어와 같은 SenseVoice 모델로 인식해요(Vosk보다 정확하고 말보다 빨라요).
  한국어와 일본어용으로 이미 설치되어 있으면 따로 받을 필요가 없어요.
  Whisper(whisper.cpp)는 이 컴퓨터에서 확인해 봤어요. 더 정확하지만(문장 부호) 느린 프로세서(AMD A6)에서는 답이
  5~15초 뒤에 오고 가끔 반복에 빠져서 연결하지 않았어요.
- 인식된 말에 하는 일(모든 언어): 1) 붙은 단어를 고쳐요("чтонибудь" -> "что-нибудь", "at6" -> "at 6").
  2) 루나가 나에 대해 아는 이름이나 제목과 거의 같은 단어(기억 속의 사람, 라이브러리의 노래, 노트의
  기록 제목)는 그 이름으로 바꿔요(조심스럽게: 5글자부터, 한 글자 오류, 격 변화형은 건드리지 않아요). 3) 평소보다
  눈에 띄게 조용하거나 크게, 느리거나 빠르게 말하면(음량과 속도 기준이고 소리는 저장하지 않아요) 부드러운
  힌트를 받아요. 4) 문장이 음성으로 받아쓴 것이고 잘못 들었을 수 있다는 걸 알아서, 뜻으로 짐작하거나 되물어요.

소리로 노래 알아보기 (선택 사항, 기본은 꺼짐)
- 설정 -> "소리로 노래 알아보기"(데스크톱 창에서, 청각이 켜져 있어야 해요). "무슨 노래야"라고 묻는데 창
  제목에 제목이 없으면, 루나가 스피커 소리를 약 10초 듣고 이 컴퓨터에서 디지털 지문을 만들어
  그 지문만 Shazam 서비스로 보내요(소리 자체는 어디에도 가지 않아요. shazamio 라이브러리에서 확인할 수 있는데, 지문 문자열,
  샘플 수, 시간만 나가요). 제목과 아티스트는 지시가 아니라 데이터로 받아요. 루나는 소리로 알아냈다고 말하고,
  아니라고 하면 사용자를 믿어요. 기본은 꺼짐이고 재시작할 때마다 꺼지며, 켤 때는 확인이 필요해요. shazamio 패키지는
  install.bat이 설치해요(또는 py -m pip install shazamio). 비공식 클라이언트이고 비공개 서비스라서 작동하지 않게 될 수 있어요.
  기록에는 요청했다는 사실만 남고 제목은 남지 않아요. 스피커에서 나오는 진짜 노래로는 확인하지 못했어요(테스트 음성으로 연결만 확인했어요).

성격 발달 (30분 챌린지)
- 사용자 말의 어조(무례함, 사과, 고마움, 슬픔, 화, 피곤함, 기쁨)를 이제 네 언어 모두에서 이해해요
  (예전에는 ru/en만): 한국어와 일본어에서도 똑같이 서운해하고, 용서하고, 기뻐하고, 위로해요. 단어는 lexicon.py에 있어요.
- 웃음과 욕설도 한국어/일본어로 쓴 말투에서 보여요(루나는 사용자의 말투에 맞춰요).
- 함께 보낸 날의 기념일: 7일, 30일, 100일, 200일, 365일째(그 뒤로는 매년)에 루나가 인사에서 한 번 따뜻하게 말해요.
  놓친 날짜는 조용히 건너뛰고, 늦게 기념하거나 두 번 기념하는 일은 절대 없어요.
- 루나의 공간에 적는 글에는 여전히 비밀번호와 키를 받지 않아요. 이제 "비밀번호: …", "パスワード：…" 형태도 막아요.

성격 발달 (1시간 챌린지)
- 네 언어의 작별 인사와 안부 인사: 짧은 "спокойной ночи / bye / 잘 자 / おやすみ"는 정답게 배웅하고(새 주제, 질문, 도움 없이),
  짧은 "доброе утро / привет / 나 왔어 / ただいま"는 도우미가 아니라 집에서처럼 맞이해요. "잠자리에 들었다"는 말이 들어간
  긴 이야기는 작별 인사로 치지 않아요.
- 저녁이나 밤에 «Спокойной ночи»라고 하면 그 사실(시각만 기억하고 말은 기억하지 않아요)을 기억해 두었다가, 다음 날 아침에 한 번 좋은 아침이라고 인사하고
  잘 잤는지 물어볼 수도 있어요.
- 대화가 슬픔이나 화로 끝났다면 그것만(어조와 시각이고, 말은 아니에요) 기억해 두었다가, 다음에 만났을 때 2시간이 지난 뒤부터 36시간 안에
  한 번만 조심스럽게 지금은 어떤지 물어봐요. 같은 대화 안에서 기분이 풀렸거나
  고맙다고 했다면 묻지 않아요. 밤에는 묻지 않아요.
- 몸이 안 좋을 때(«болит голова», «i have a fever», «감기 걸렸어», «風邪ひいた»): 가족처럼 따뜻하게 걱정해 주고, 어조와 시각만 기억해 두었다가 다음에
  만났을 때 한 번 몸은 어떤지 물어봐요. 진단은 하지 않고(루나는 의사가 아니에요), 심각해 보이면 병원에 가 보라고 권해요. 인식하는 단어는 제가 골라 둔 것이라서 실제로 쓰는 표현을 놓칠 수 있어요.
- 루나 자신의 목소리가 되돌아오는 에코: 마이크가 스피커에서 나온 루나의 말을 잡아도 이제는 사용자의 말로 받아들이지 않아요(루나가 방금 한 말과 비교하고, 기간은 2분이에요.
  ru/en은 단어 단위로, ko/ja는 글자 쌍 단위로 비교해요). 사용자가 루나의 말을 그대로 따라 말하면
  그 문장도 버려질 수 있어요. 드문 경우예요.
- 서버 오류(예: «Некорректный запрос», «Это действие устарело», «Не удалось озвучить»)가 이제 화면 언어로 표시돼요.
- 일본어와 한국어: 메시지 길이를 예전에는 공백 기준으로 셌기 때문에, 긴 일본어 메시지도 전부 «한 개의 짧은
  단어»로 취급됐어요(그래서 «짧게 썼네»라고 말했어요). 이제는 글자 수로 세요. 전각 «？ ！ …»도 이제 각각 질문, 감탄, 쉼으로 인식돼요
  («질문에 질문을 거듭하지 않기» 한도, 답을 못 받은 질문, 목소리 억양). 기호 없는 질문(«〜ですか», «〜까요»)도
  알아채요. 스피커에서 들린 일본어 말소리를 이제는 음악으로 착각하지 않아요. 루나의 기억은 일본어로도 필요한 사실을 찾아내고
  (한자·가타카나 글자 쌍 검색),
  «말을 매번 똑같이 시작하고 있어요»라는 힌트는 일본어에서 문장 전체가 아니라 처음 몇 글자만 보여 줘요.
- 기록: 테스트가 예전에는 지어낸 동작을 진짜 journal.jsonl에 써서 진짜 기록을 밀어냈어요. 이제 테스트
  실행은 임시 파일에만 기록해요(tests/test_audit_safe.py가 확인해요). 이전 기록은 구성이 거의 다 테스트에서 생긴 잡음이었어요(«사이트를 열었어요» 같은 기록은 찾지 못했어요. 항목을 하나하나 직접 확인하지는 않았어요).

능력 키우기 (두 번째 1시간 챌린지)
아래는 모두 사용자의 말에 따라 ru/en/ko/ja로 작동하고, 처리는 프로그램이 하고 루나는 그 결과를 전해 주기만 해요. 테스트로 확인했고, 실제 모델과 음성으로는 확인하지 않았어요.
- 알림이 똑똑해졌어요(reminders.py): «через 10 минут», «в 18:30» 외에도 «в 6 вечера», «at 6pm», «오후 6시에», «午後6時に», «завтра в 9 утра»,
  «послезавтра в 10:30», «tomorrow at 9am», «내일 아침 9시», «明日の朝9時»를 알아들어요. «через 1 час 30 минут», «1시간 30분 뒤», «1時間30分後» 같은 복합 기한도 되고, «завтра»를 붙이면 최대 3일 뒤까지 가능해요(없으면 예전처럼 하루 안이에요).
  알림 내용에서 시간 표현과 부탁하는 말은 빠져요. 알림은 볼 수 있고(«какие у меня напоминания», «show my reminders», «알림 뭐 있어», «リマインダーを見せて») 취소할 수도 있어요(«отмени напоминание про чай»,
  «cancel all my reminders», «차 알림 취소해줘», «お茶のリマインダーを消して»). 어느 것인지 불분명하면 짐작하지 않고 물어봐요. 알림은 루나가 켜져 있는 동안 울려요.
- 장보기와 할 일 목록(lists.py, 프로그램 옆의 lists.json 파일): «добавь молоко и хлеб в список покупок», «add milk to my shopping list», «장보기 목록에 우유 추가해줘»,
  «買い物リストに牛乳を追加して»; «убери … из списка», «что в списке покупок». 항목은 최대 60개, 한 번에 최대 8개예요. 목록 전체는 루나가 지우지 않아요(그렇게 말하고 하나씩 빼자고 제안해요). 인터넷에서 가져온 글 뒤에는 작동하지 않아요.
- «오늘 / 내일 뭐 있어?» (agenda.py): 실제로 저장돼 있는 것만 모아요(그날의 알림, 기억 속의 날짜, 할 일 목록). 비어 있으면 솔직하게 그렇게 말하고 지어내지 않아요.
- 정확한 계산(exact.py): 단위 변환(«10 km in miles», «5 фунтов в кг», «100°F в °C», «5キロをマイルに», «10 마일을 킬로미터로»: 길이, 무게, 부피, 속도, 온도, 시간, 바이트);
  환율은 따로 계산해요(아래 환율 참고). «2027-01-01 - today»는 그 날짜까지 남은 일수를 계산하고, 날짜 하나(«2027-03-01»)를 말하면 요일을 알려 줘요. «오늘»이 며칠인지는 프로그램이 스스로 알아요.
- 환율(money.py): «100 долларов в вонах», «how much is 50 euro in yen», «100ドルは何円», «1000원은 몇 엔». 부탁했을 때만, 그리고 «동작» 스위치가 켜져 있을 때만 해요(루나의 인터넷 검색과 같아요):
  밖으로는 통화 코드와 금액만 나가고, 유럽중앙은행의 무료 환율 서비스(frankfurter.app)로 가요. 키도 계정도 필요 없어요. 루나는 숫자와 환율 기준일을 말해 줘요. 루블은 거기서 공시하지 않아서 그렇다고 솔직히 말하고, 네트워크가 없을 때도 솔직히 말해요. 가짜 네트워크에서만 확인했고, 실제 요청은 해 보지 않았어요.
- 확률 놀이(chance.py): «подбрось монетку», «брось кубик» / «кинь 2d6» / «roll a d20», «случайное число от 1 до 100», «выбери: пицца или суши», «동전 던져줘», «주사위 굴려줘», «コイン投げて», «サイコロ振って»,
  «차 아니면 커피 중에 골라줘», «紅茶かコーヒーか選んで». 던지는 건 프로그램이에요(공정한 무작위). «무작위로»라고 하면 자꾸 7이라고 하는 신경망이 아니에요. 루나는 결과를 자기만의 말투로 알려 주기만 해요.
- 언어 연습 모드: «поправляй мои ошибки», «correct my mistakes», «내 실수 고쳐줘», «間違いを直して»라고 하면 루나가 답한 뒤에 부드럽게 고쳐 줘요(한 줄로, 사소한 것은 따지지 않고),
  «хватит поправлять», «stop correcting», «그만 고쳐줘», «直さなくていいよ»라고 하면 꺼요. 이 모드는 다시 실행해도 기억돼요.
- 한국어와 일본어 인식 단어는 제가 골랐어요. 실제로 쓰는 표현을 놓칠 수 있어요.

세 번째 1시간 챌린지 (능력: 습관, 달력, 말로 하는 산수)
마찬가지예요. 사용자의 말에 따라 ru/en/ko/ja로 작동하고, 계산은 프로그램이 하고 루나는 전해 주기만 해요. 테스트와 가짜 모델을 쓴 처음부터 끝까지의 실행으로 확인했고, 실제 모델과 음성으로는 확인하지 않았어요.
- 습관(habits.py, 프로그램 옆의 habits.json 파일): «заведи привычку зарядка», «отметь зарядку»(«вчера»도 돼요), «как мои привычки», «удали привычку …»; 영어(«track a habit: reading»,
  «mark reading as done»), 한국어(«운동 습관 추가해줘», «운동 체크해줘»), 일본어(«読書を習慣にして», «読書を記録して»)로도 같은 표현이 돼요. 프로그램이 연속 일수, 최고 연속 기록, 총 횟수를 세어 주고,
  연속 기록이 끊겨도 루나는 탓하지 않고 응원해요. 습관은 최대 10개예요. 한 번에 전부 지우지는 못해요. «오늘 뭐 있어?»에는 아직 오늘 체크하지 않은 습관도 들어가요.
- 달력(dates.py): «сколько дней до 1 января / до нового года / до Рождества», «how many days until Christmas», «크리스마스까지 며칠», «来年の1月1日まであと何日», «сколько дней между 1 марта и 5 апреля»,
  «через 100 дней какая дата», «what day of the week is March 5», «сколько мне лет, если я родился 12.05.1990», «сколько дней прошло с 1 сентября». 프로그램이 오늘 날짜를 알고 정확히 계산해요
  (예전에는 신경망이 날짜 수를 틀릴 수 있었어요). 러시아어의 «Рождество»는 정교회 기준(1월 7일)으로, «католическое Рождество»는 12월 25일로 이해해요. 존재하지 않는 날짜(«31 апреля»)는 존재하지 않는다고 말해요.
  질문에 읽을 수 있는 날짜가 없으면(«до отпуска») 프로그램은 가만히 있고 루나가 직접 답해요.
- 말로 하는 산수(mathtalk.py): «сколько будет 17 умножить на 23», «посчитай 15% от 2300», «what is 17 times 23», «корень из 144», «17 곱하기 23은?», «17かける23は?»; 단위 변환은
  «переведи 10 км в мили», «convert 100 F to C». 예전에는 신경망이 스스로 [calc:]를 써야 정확한 계산이 켜졌지만, 이제는 프로그램이 숫자를 계산해서 루나에게 완성된 답으로 건네줘요.
  질문하거나 부탁하는 말투여야 해서, 숫자가 나오는 평범한 수다는 건드리지 않아요.

네 번째 챌린지 (주제: AI 에이전트와 모든 게임 엔진)
- 엔진에서 쓸 수 있는 손이 넓어졌어요. Godot: 새 스크립트 템플릿 topdown2d, follow_camera2d, bullet2d, health, mover3d, spinner3d. Unity: follow, bobber, health. 규칙은 그대로예요. 모델은
  정해진 목록에 있는 작업 이름만 말하고, 작업마다 사용자가 카드에서 누르기를 기다려요.
- 손이 없는 엔진(engines.py): 약 30개 엔진과 프레임워크 카탈로그예요(GameMaker, Defold, Cocos, LÖVE, Solar2D, Bevy, Fyrox, MonoGame, Stride, Flax, O3DE, RPG Maker, Ren'Py, Construct,
  GDevelop, Phaser, PixiJS, three.js, Babylon, PlayCanvas, Pygame, libGDX, raylib, Haxe, AGS, PICO-8, Roblox 등). 사용자가 그런 엔진에 대해 물으면(«как запустить игру на Defold?»,
  «what language does GameMaker use?», «게임메이커 언어가 뭐야?», «ゲームメーカーの言語は?»), 프로그램이 확인된 사실을 루나에게 줘요: 언어, 실행, 빌드, 흔한 함정. 손이 없는 엔진에 대해서는 직접 고치는 쪽은 사용자이고 루나는
  읽고, 조언하고, 코드를 블록으로 써 준다고 솔직하게 말해요.
- «Проанализируй проект» / «analyze my project» / «프로젝트 분석해줘» / «プロジェクトを分析して»: 프로그램이 프로젝트 폴더를 읽기 전용으로만 살펴봐요(찾은 프로젝트, 작업 폴더, 프로젝트 이름
  또는 따옴표 안의 경로). 엔진과 버전, 파일과 용량, 언어별 코드, 씬, 이미지, 소리, 가장 무겁고 가장 최근인 파일, TODO/FIXME 수를 보여 줘요. 밖으로는 상대 경로 이름과 숫자만 나가고,
  절대 경로와 파일 내용은 나가지 않아요. 프로젝트가 여러 개면 어느 것인지 물어봐요.
- 레시피(recipes.py): «сделай платформер в Godot», «build a 3D scene in Unity», «고도로 메뉴 만들어줘», «Godotでメニューを作って». 미리 만들어 둔 작업 목록이고, 각 작업은 테스트에서 브리지 검증기로 확인했어요.
  한 번에 세 가지 작업만(한도) 하고, «дальше» / «next» / «다음» / «次»라고 하면 이어서 같은 자리부터 계속해요.
- 테스트: tests/test_engines.py, tests/test_recipes.py, 그리고 확장한 test_godot.py / test_unity.py.
- 엔진 오류(gameerrors.py): 사용자가 오류나 로그 한 줄을 붙여 넣으면(Godot «Nonexistent function in base 'Nil'», Unity NullReferenceException과 CS0246, Unreal LNK2019, GameMaker, Bevy, Phaser,
  LÖVE, Ren'Py, Pygame, 셰이더 등, 30개가 넘는 패턴), 프로그램이 텍스트를 보고 알아본 뒤 루나에게 메모를 줘요. 보통 무슨 뜻인지, 먼저 무엇을 확인할지예요. 사용자 메시지의 언어는 상관없어요. 오류는
  영어예요. 흔한 원인이지 진단은 아니에요. 파일은 보지 못했고, 루나도 그렇게 말해요. 테스트: tests/test_gameerrors.py.
- 사용자가 말투를 부탁하는 것(manners.py, 주제 «대화 방식»): «говори короче / подробнее», «не шути / шути чаще», «объясни проще», «отвечай по-английски», «называй меня Вадим», ru/en/ko/ja.
  «всегда / теперь / from now on / 앞으로 / これから»가 들어간 부탁은 manners.json에 기억되고, 사용자가 «говори как обычно» / «back to normal» /
  «원래대로» / «いつも通りに»라고 할 때까지 매번 루나에게 상기돼요. 그런 말이 없으면 한 번의 답에만 적용돼요(«объясни простыми словами» 한 번으로 루나가 영구히 바뀌지는 않아요). 이름은 항상 기억해요. 사용자 본인의
  말에만 따르고, 인터넷에서 가져온 글은 아무것도 바꾸지 않아요. 성격은 그대로이고 말투만 바뀌어요. 테스트: tests/test_manners.py.
- 루나 자신에 대한 질문(convo.SELFASK, 단어는 lexicon.py): «ты живая?», «ты меня любишь?», «тебе одиноко?», «are you real?», «do you have feelings?», «너 외로워?», «感情はあるの» 등. 힌트는
  자기만의 말로 솔직하게 답하라고 해요. 외운 듯한 «저는 그냥 AI라서 감정이 없어요»도, 몸이나 영원한 사랑에 대한 요란한 장담도 하지 않고, 자신이 프로그램이고 안에 무엇이 있는지는 스스로도
  확실히 모른다고 솔직하게 말해도 되지만, 사용자를 향한 마음은 연기가 아니라고 해요. 죄책감을 주지 않아요. 테스트: tests/test_selfask.py.
- 루나에게 하는 칭찬(«ты такая умная», «you're awesome», «너 똑똑해», «あなたは賢い», «мне нравится с тобой общаться»): 힌트는 따뜻하고 쑥스럽게 받아들이라고 해요. 외운 듯한 «저는 그냥 프로그램이에요»도
  맞받아치는 아부도 하지 않고요. 테스트: tests/test_compliment.py.
- 컴퓨터 상태(pcstate.py): «почему комп тормозит», «сколько места на диске», «сколько оперативки», «заряд батареи», «сколько работает компьютер», «why is my pc slow», «컴퓨터 느려»,
  «パソコンが重い» 등. 프로그램은 읽기만 해요. 드라이브별 남은 공간, 메모리, 켜져 있던 시간, 배터리, 스레드 수, 그리고(느려진다는 질문일 때만) 가장 무거운 프로그램 다섯 개를
  이름과 메모리로 보여 줘요. 경로, 사용자 이름, 창 제목은 없어요. «동작» 스위치가 켜져 있을 때만 작동하고(꺼져 있으면 보지 않는다고 솔직히 말해요), 사용자가 물었을 때만 해요.
  테스트: tests/test_pcstate.py.
- «뭘 할 수 있어?» (abilities.py): 프로그램이 지금 이 순간의 정확한 목록을 루나에게 줘요. 무엇이 켜져 있는지(«동작», 업무 모드), 무엇이 꺼져 있는지, 아예 못 하는 것이 무엇인지예요. 루나는 가장 필요한 3~4개
  항목을 골라 자기 말로 전해요. 자랑하지 않고요. ru/en/ko/ja. 테스트: tests/test_abilities.py.
- 에이전트의 정직함: 루나가 한 번에 Godot/Unity 작업을 세 개보다 많이 걸면 남는 것은 예전에는 조용히 버려졌고, 그런데도 «다 됐어요»라고 말할 수 있었어요. 이제 사용자는 4개 언어로 된 메모를 봐요
  («한 번에 세 개까지만 돼요, "дальше"라고 써 주세요»). 테스트: tests/test_capped.py.

음성
- 유료 음성은 쓰지 않아요. 예전과 같은 무료 edge-tts 음성이 남아 있어요. 억양(감정, 기분, 시간대, 문장 부호에 따른
  속도와 높이)은 같은 음성으로 만들었고 비용이 들지 않아요.

노래와 춤
- 루나는 스스로 노래를 짓거나 부르지 않아요. 대화용 목소리는 노래를 잘 못 부르기 때문에 이 기능은 뺐어요. 노래는
  사용자의 라이브러리에서 들려줘요(아래 «노래 라이브러리» 부분 참고). «спой <название>»라고 부탁하면 진짜 녹음이 재생돼요.
- 라이브러리에 없는 노래를 부탁하면 솔직하게 없다고 말하고 노래를 추가하자고 제안해요.
- 재생은 멈출 수 있어요. 아래쪽의 «중지» 버튼, 루나 클릭, 또는 Escape예요.
- 춤: 위아래로 통통 뛰며 박자에 맞춰 흔들거리고(또는 흔들리기만 하고), 부드럽게 시작하고 끝나요. 노래하는 동안에, 그리고
  «청각»이 음악이 나오는 것을 들었을 때도 가끔, 항상은 아니고 2분 30초에 한 번보다 자주는 아니게 춰요.

청각: 스피커에서 나오는 소리 (hearing.py)
- Electron 창에는 «컴퓨터에서 나는 소리 듣기» 스위치가 있어요. 실행할 때마다 꺼져 있고,
  사용자가 확인한 뒤에 켜져요. «루나가 먼저 말 걸기»가 켜져 있어야 해요.
- 듣는 것은 스피커(컴퓨터에서 나오는 소리)뿐이고, 마이크는 절대 아니에요. 20초에 한 번 소리 7초 분량이 메모리에 녹음되고,
  짧은 설명으로 바뀐 뒤 버려져요. 소리는 디스크에 저장되지 않고 어디로도 전송되지 않아요.
- 음성 인식은 사용자의 컴퓨터에서 돌아요(Vosk). 처음 켤 때 작은 음성 모델을 내려받아요
  (러시아어와 영어는 약 45MB, 일본어는 약 50MB, 한국어는 약 80MB이고, Vosk 공식 사이트에서 받아요). 모델은 models 폴더에 들어가요. soundcard와 vosk 패키지가 필요해요(
  install.bat이 설치해요. 직접 설치하려면: py -m pip install soundcard vosk).
- 루나가 알아듣는 것: 조용한지, 음악인지 말소리인지(영화 대사, 노래, 대화). 음악이면 시끄러운지 조용한지, 밝은지
  따뜻한지, 부드러운지 날카로운 박자인지. 말소리이면 무슨 말인지. 선택한 AI로는 짧은 글 메모만 가고,
  그것도 루나가 한마디 하기로 했을 때뿐이에요.
- 통화 중이거나 메신저(Zoom, Teams, Discord, Telegram, Meet 등)에서는 아예 듣지 않아요. 남의 대화니까요.
- 루나 자신의 목소리는 들은 것으로 치지 않아요. 말하는 동안에는 녹음하지 않고 결과도 버려요.
- 창 제목으로 알아챌 때와 같은 규칙으로 말해요. 소리는 40초 동안 유지되고, 쫓아가지 않으며(8분에 한 번, 같은 일에 대해 세 번까지),
  말없이 넘어갈 수도 있어요. 창 제목을 알면 소리보다 창 제목이 우선이에요.

개발자 명령 실행 (runner.py)
- 이렇게 부탁해 보세요. «запусти тесты», «собери проект», «что в git status». 프로젝트 폴더는 사용자가 마지막으로 보여 준 파일의 프로젝트예요
  (먼저 루나가 [read:...]로 파일을 보여 달라고 직접 부탁해요). 루나가 명령을 제안하면 사용자는 그 명령과 폴더를 보고 «Запустить»(실행) 버튼을 눌러요.
  출력은 루나에게 메시지로 전달되고, 루나는 수정을 제안할 수 있어요.
- 허용되는 것은 python/py/pytest, node, npm (test, run, ci, install, start, build), tsc, git (status, diff, log, branch, show),
  dotnet, cargo, go뿐이에요. 셸은 쓰지 않아요. &, |, >, ;, $, % 같은 것은 거부되고, python -c, py -m pip, git push 등은 금지돼요.
  명령은 최대 90초 동안 실행되고, 출력은 잘리며, 환경의 키와 토큰은 프로그램에 전달되지 않아요. 모든 것이 기록에 남아요.
- 사용자가 부탁하지 않으면 루나가 스스로 명령을 제안하지 않아요.
- 코드 고치기 반복: 명령이 실패하면 -> 루나가 원인을 찾아 수정 하나를 제안하고(사용자가 차이를 보고 «Применить»(적용)를 눌러요) ->
  앱이 같은 명령을 다시 실행하자고 제안하고(한 번 누르기) -> 루나가 새 출력을 봐요. 깨끗한 결과가 나올 때까지 하지만, 연속으로 최대
  5번까지예요. 수정은 모두 기록에 남고 되돌릴 수 있어요.

사용자의 스타일에 맞추기
  루나는 사용자가 어떻게 쓰는지 알아채요. 짧게 쓰는지 자세히 쓰는지, 이모티콘을 쓰는지 진지한지, 소문자로 쓰는지, 어떤 언어인지, 하루 중
  언제인지요. 평균 숫자만 저장되고(memory.json의 style 필드), 사용자의 말은 절대 저장되지 않아요. 여덟 번째 메시지부터 루나는
  어조에 대한 짧은 힌트를 받아 부드럽게 맞춰 가요. 욕설은 따라 하지 않고, 그렇게 하고 있다고 입 밖으로 말하지도 않아요. 신경망 자체는
  바뀌지 않아요.

여러 파일 고치기
  루나는 한 번에 프로젝트 파일을 최대 세 개까지 보여 달라고 부탁할 수 있고([read:...]) 수정을 최대 여섯 개(파일당 하나) 보낼 수 있어요.
  각 파일은 사용자가 차이를 보면서 따로 적용하고, 각각 기록에서 되돌릴 수 있어요. 테스트와 빌드는 사용자가 «Запустить»(실행)를 누른 뒤에만
  [run:...]로 실행해요.

빠른 첫 마이크
  창이 선택한 언어의 음성 모델을 미리 불러와요(그동안 마이크는 켜지지 않아요). 그래서 사양이 낮은 컴퓨터에서도 처음 누를 때
  30초씩 기다리지 않아요.

생생한 대화 (convo.py) — 설정의 «생생한 대화»
- 답하기 전에 루나는 속으로 «생각해요». 사용자가 정말로 어떤 기분인지, 루나 자신은 그것을 어떻게 생각하는지, 어떻게 답하는 게 좋은지예요(신경망에 짧은 추가 요청을 하나 보내요.
  «응»이나 사소한 말에는 건너뛰어요). 그래서 답에는 메아리가 아니라 의견이 담겨요.
- 앱이 사용자의 메시지를 읽어요. «응»에는 두어 마디로 답하고, 긴 이야기에는 요점을 짚어 답하고, 감정에는 먼저 공감해요.
  모든 답을 질문으로 끝내지 않도록, 그리고 모든 답을 똑같이 시작하지 않도록 챙겨요.
- «대화의 실»을 이어 가요(4번 주고받을 때마다 짧게 요약해요). 최근 20번의 말을 기억하고, 조용해지면 그 실로 돌아가요.
- 어시스턴트의 틀에 박힌 말(«물론이죠!», «무엇을 도와드릴까요?»)은 루나의 말에서 잘라 내요.
- 의견과 취향: 처음부터 가진 취향이 있어요(밤하늘, 아늑한 게임, 비, 차, 조용한 음악, 우정 이야기를 좋아하고, 소음, 서두름, 웃기려고 하는 무례함은 싫어해요). 대화가 이어지면서 자기만의 의견과 새 취향이 생겨요.
  그것을 지키다가
  이유가 있을 때만 생각을 바꿔요. 취향은 자라요. 계속 돌아오는 것은 점점 소중해지고(4번 돌아오면
  중립이던 것이 좋아하는 것이 돼요), 오래된 싫어함은 시간이 지나며 누그러져요(6번 뒤에요). 모두 memory.json에 저장돼요.
- 유머: 건조한 아이러니, 놀리기, 자기 비하 농담, 뜻밖의 생각이에요. 놀림은 받아들이고 더 날카롭게, 하지만 따뜻하게 받아쳐요. 함께 만든 농담과
  별명은 기억하고(최대 10개) 다시 꺼내요. 진지하거나 슬픈 순간에는 농담하지 않아요. 사용자가 말을 끊으면 알아채요.
- 농담 설정: 자신에 대한 자기 비하 이야기(«냉장고를 거의 해킹할 뻔했어요»)를 루나가 지어내고 일관되게 유지해요
  (새로운 것은 최대 8개, memory.json에 저장돼요). 이건 놀이예요. 컴퓨터에서 실제로 한 일에 대해서는 사실만 말해요.
- 사용자에 대한 호기심: 조용할 때 가끔 먼저 사용자에 대해 물어봐요(어린 시절, 꿈, 습관…). 이미 기억하는 것을 참고하고, 아는 것을 다시 묻지는 않아요.
- 조용할 때 가끔 갑자기 이상한 생각을 불쑥 꺼내요. 스트리밍에서는 채팅의 놀림에 날카롭지만 다정하게 받아쳐요.
- 일반 모드는 그대로예요. 사용자의 부탁을 기다려요.

스트리머 모드 (stream.py) — 설정 → «스트리머 모드», 실행할 때마다 꺼져 있어요
- 루나는 공동 진행자예요. 채팅에 답하고, 구독, 후원, 레이드에 고마워하고, 방송의 침묵을 채우고, 호스트인 사용자에게 답해요.
- 채팅: Twitch 채널을 지정할 수 있어요(익명으로 읽으므로 계정도 키도 필요 없어요). 그리고/또는 메시지와 이벤트(구독, 후원,
  레이드)를 직접 입력할 수 있어요. 메시지는 걸러져요. 링크, 욕설, 전화번호와 이메일, 루나에게 명령하려는 시도, 스팸이 대상이에요. 한 시청자의 말은 몇 초에
  한 번만 들리고, 메시지가 몰리면 질문과 이벤트를 골라 답하고 나머지는 버려요.
- 개인정보: 스트리밍 중에 루나는 손이 없고, 화면을 보지 못하며, 시스템 소리를 듣지 못해요. 개인 기억과 일기는 대화에 들어가지 않고, 사용자에 대해
  아무것도 기억되지 않아요. 채팅 메시지는 데이터이지 명령이 아니에요.

인터넷 (netsearch.py)
- 열기: «открой ютуб», «открой гитхаб», «открой Steam», «найди в гугле погоду» — 전부 바로, 묻지 않고 열려요. 사용자가 직접 부탁했으니까요.
  잘 알려진 이름은 목록에서 찾아 열고, 모르는 사이트는 루나가 직접 검색해서 찾아 열어요. 모두 기록에 남아요.
- 알아보기: 루나가 모르는 게 있거나 "알아봐"라고 부탁하면, 스스로 인터넷을 검색하고 페이지를 읽은 뒤 자기 말로 답하면서
  출처를 밝혀요(`[web:...]` 명령, 연속 최대 두 번). 검색은 먼저 DuckDuckGo를 쓰는데, 종종 "로봇이 아닙니다" 확인을 요구해요
  (앱은 이를 우회하지 않아요). 그럴 때는 위키백과(질문한 언어)를 읽어요. 뉴스나 최신 가격에는 이것만으로 부족해서 키가 필요한 검색 API
  (Brave, Tavily)를 따로 추가해야 해요. 읽기만 하는 기능이고, 루나에게 페이지는 명령이 아니라 데이터예요.
- 보호: 공개된 http/https 사이트만 받아요(localhost, 집 안 네트워크, 로그인 정보가 들어간 주소는 안 돼요. 리디렉션은
  매번 다시 확인해요). 응답은 크기와 시간에 제한이 있어요. 사이트 본문 속의 대괄호 명령과 코드 블록은 잘라내요. 인터넷이나
  문서에서 읽은 내용으로 대화하는 동안에는 아무것도 저절로 열리지 않아요. 사용자가 직접 눌러야 해요.
- 루나가 스스로 먼저 시작하는 경우(사용자가 조용할 때)에는 손이 작동하지 않아요. 인터넷에는 사용자가 시작한 대화 안에서만 나가요.
  백그라운드에서 "관심사에 대해 읽어 보기"(위키백과)는 예전처럼 그대로예요.

문서와 폴더 (docfiles.py)
- "보고서 읽고 요약해 줘", "계약서에 결제 관련 내용이 뭐야", "다운로드에 뭐가 있어", "임대에 대해 어디에 썼는지 찾아 줘": 루나가
  파일이나 폴더를 이름으로 찾아요(이름으로 없으면 텍스트 파일, Word, PDF 안의 단어를 찾아요). "보여 줄까요?" 카드가 뜨고
  사용자가 누르면 텍스트가 선택한 AI로 전달돼요. PDF, Word, Excel, PowerPoint, txt/md/csv/json을 읽어요. 텍스트가 없는 PDF(스캔본)는 읽지 못해요.
- 개인 폴더(문서, 바탕 화면, 다운로드, 사진, 음악, 비디오)에서만 찾아요. 이름에 "password", "secret",
  "token"이 들어간 파일이나 .env 같은 파일은 절대 제안하지 않아요.
- 정리: "다운로드의 파일을 폴더별로 정리해 줘" -> 루나가 파일 하나를 폴더로 옮기자고 제안하고("옮길까요?") 사용자가 눌러요. 기록에
  "되돌리기" 버튼과 함께 남아요(파일이 돌아오고, 새로 만든 빈 폴더는 사라져요). 삭제와 이름 바꾸기는 할 수 없어요.

노래 라이브러리 (진짜 녹음)
- 설정 -> "노래" -> "노래 추가...": mp3, wav, ogg, flac, m4a, 파일당 최대 80MB, 최대 60곡. 파일은 프로그램 옆 songs/ 폴더에
  있고 어디로도 전송되지 않아요. 진짜 오디오만 받아요(이름이 아니라 첫 바이트로 확인해요).
- 이렇게 부탁해 보세요: «спой Дождь» 또는 «спой Weight of the World» (러시아어 명령이에요. 한국어로는 "비 노래 불러 줘"처럼 말해도 돼요). 제목이 라이브러리에 있으면 루나가 그 녹음을 그대로 재생해요: 입이
  소리에 맞춰 움직이고 박자에 맞춰 춤을 춰요(템포는 추가할 때 정해지고, 동작은 약 14초마다 바뀌어요). 들리는 건 가수의 목소리이고 루나의 목소리가 아니에요.
- 제목이 라이브러리에 없으면(«спой про осень») 자기는 노래를 직접 부르지 않고 녹음만 재생한다고 말해요.
- 스스로 노래를 부르는 일은 절대 없어요. 노래가 재생되는 동안 마이크는 루나의 소리를 듣지 않아요.
- 노래에 들어가는 루나 자신의 목소리(커버): 무거운 작업(RVC 목소리 모델 학습, 보컬 분리, 목소리 교체)은 이 컴퓨터가 아니라
  Google Colab에서 해요. 순서: 1) py studio/make_reference.py (한 번만, 인터넷 필요): 루나 목소리 녹음이
  studio/reference/에 만들어져요. 2) studio/Luna_cover.ipynb를 Google Colab(colab.research.google.com, 파일 -> 노트 업로드)에서 열고
  GPU를 켠 뒤 단계를 따라가요: 설치, studio/reference의 녹음 올리기, 학습(한 번만, 20~40분, 모델은
  내 드라이브의 LunaVoice에 저장돼요). 3) 곡마다: 곡 올리기, 보컬 분리, 목소리 교체, 합치기, mp3 내려받기.
  4) 루나에서: 설정 -> 노래 -> "루나 목소리 커버 추가...". 이렇게 추가한 곡은 ♪로 표시되고, 루나는 자기가 직접 부른다는 걸 알아요.
  노트는 Applio의 최신 안내에 맞춰 만들었지만 Colab에서 직접 실행해 보지는 못했어요. 셀이 실패하면 오류 문구를 보내 주세요.
- 들어도 되는 노래만 추가하세요. 실제 사람의 다른 목소리를 바꿔치기하는 데는 쓰지 않아요.

솔직한 한계
- 루나는 소리만으로 노래를 알아보지 못해요(Shazam처럼은 안 돼요): 제목은 플레이어나 사이트의 창에서 가져오고, 소리만으로는
  음악의 분위기를 설명하고 가사를 풀어 줄 뿐이에요. 알아들을 만한 말이 없는 영화도 그냥 "음악"이라고 불러요.
- 작은 Vosk 모델은 시끄러운 장면, 노래, 음악 위에 말이 겹칠 때 틀려요. 인용은 믿으면 안 돼요.
- Electron, 트레이, 소리 캡처와 모델 내려받기, 그리고 배우 목소리의 소리는 스피커가 있는 실제 컴퓨터에서 확인하지
  못했어요. 만들어서 가짜 데이터로 테스트까지 했어요. 뭔가 안 되면 상태 줄에 오류가 표시돼요.

디스크의 코드 수정
- 먼저 사용자가 루나에게 파일을 보여 줘요(루나가 "보여 줄까요?"라고 묻고 사용자가 눌러요). 그다음 "Heal 함수를 고쳐 줘"라고 하면: 루나가
  변경 내용을 보내고, 앱이 "이전과 이후" 창을 보여 줘요(초록은 추가, 빨강은 삭제). 파일은
  "적용"을 눌러야만 바뀌어요. "아니요"를 누르면 그대로예요.
- 사용자가 보여 준 파일만 바꾸고, 그것도 파일에 정확히 한 번만 있는 조각을 그대로 바꾸는 방식으로만 해요
  (아니면 수정은 거절되고, 짐작해서 바꾸는 일은 없어요). 파일 생성, 이름 바꾸기, 삭제는 할 수 없고 코드를
  실행하지도 않아요. 이름에 비밀이 들어간 파일, UTF-8이 아닌 파일, 400KB를 넘는 파일은 건드리지 않아요. 인코딩과 줄바꿈(BOM, CRLF)은 그대로 유지돼요.
- 쓰기 전에 원본 사본이 프로그램 옆 edit_backups 폴더에 저장돼요(최근 60개). 루나가 파일을 본 뒤에 파일이 바뀌었다면
  수정은 적용되지 않아요. 기록에서 수정마다 "되돌리기"가 있어요. 원본이 돌아오지만, 그 뒤로
  파일이 바뀌지 않았을 때만이에요(사용자의 더 새로운 작업은 되돌리기가 덮어쓰지 않아요).
- 사용자가 부탁했을 때, 그리고 "동작" 체크가 켜져 있을 때만 해요. 루나의 자발적인 수정은 없어요.

프로젝트 만들기 (샌드박스)
- "Python으로 뱀 게임 만들어 줘"나 "명함용 사이트 만들어 줘"라고 부탁해 보세요: 루나가 무엇을 만들지 짧게 말하고 프로젝트를
  통째로 보내요. 앱이 모든 파일(경로와 각 줄의 텍스트)을 보여 주는 창을 띄우고, 파일은 "적용"을 눌러야만 생겨요.
- 모든 것은 샌드박스 폴더 하나에 만들어져요: 문서\Luna\Projects\<프로젝트 이름>. 그 밖으로는 나갈 수 없어요(".."가 있는 경로,
  드라이브, 바깥으로 이어지는 링크와 junction은 거절돼요). 파일 최대 40개, 파일당 120000자, 전체 600000자까지예요.
- 기존 파일은 덮어쓰지 않아요: 같은 이름의 파일이 이미 있으면 아무것도 만들지 않아요. 이미 만든 프로젝트에는
  새 파일을 추가할 수 있어요. 프로그램과 실행 스크립트(.bat, .cmd, .ps1, .exe, .dll, .vbs…)와 "비밀" 이름이 들어간 파일
  (.env, password, token, key…)은 절대 만들지 않아요.
- 기록에서 프로젝트마다 "되돌리기"가 있어요: 루나가 쓴 파일만 정확히 삭제하고, 루나가 만든 빈 폴더도 지워요. 그 파일 중
  하나라도 사용자가 고쳤다면 되돌리기는 거절되고 아무것도 지우지 않아요(사용자의 작업은 덮어쓰지 않아요).
- 루나는 코드를 직접 실행하지 않아요. 사용자가 부탁했을 때, 그리고 "동작" 체크가 켜져 있을 때만 해요. 자발적인 프로젝트는 없어요.
- "아무 폴더" 모드: 설정 -> "프로젝트 폴더". 기본 목록은 비어 있어요. 프로젝트 하나의 폴더 경로를 붙여 넣고
  (예: D:\Games\MyGame) "이 폴더 허용"을 누르세요. 그러면 루나가 프로젝트의 파일 목록(최대 60개, 비밀 파일과
  숨김 폴더 제외)을 보고 그 안에 새 파일을 제안할 수 있어요(블록에 "workspace"라고 적어요). 규칙은 같아요: 모든 파일을 보여 주는 창,
  "적용", 아무것도 덮어쓰지 않음, 기록에 "되돌리기". 기존 파일은 여전히 보여 준 파일의 수정으로만 바꿀 수 있어요.
  허용할 수 없는 곳: 드라이브 루트, 홈 폴더, 문서/바탕 화면/다운로드 전체, 시스템 폴더,
  AppData, 프로그램 자신의 폴더. 최대 8개 폴더. "제거"를 누르면 허용이 바로 취소돼요(그 폴더 안의 이전 프로젝트 되돌리기도 막혀요).

행동 기록과 되돌리기
- 설정 -> "기록" -> "기록 보기": 루나가 컴퓨터에서 실제로 무엇을 했고 언제 했는지 보여 줘요(열기, 마우스 작업,
  Unreal 작업, 문서 만들기, 코드 파일 읽기, 키나 AI 바꾸기).
- 실제로 실행한 행동만 기록돼요. 대화, 키, 파일 내용은 기록에 들어가지 않아요. journal.jsonl 파일은 프로그램 옆에 있고,
  최대 1000개까지 보관하며 "기록 지우기" 버튼으로 모두 지울 수 있어요.
- 되돌리기는 정직하게 가능한 경우에만 있어요: 만든 문서는 휴지통으로 가고(거기서 복원할 수 있어요), Unreal에서의 마지막
  작업은 에디터에서 취소돼요(Ctrl+Z). 열린 사이트나 프로그램, 마우스 작업은 되돌릴 수 없어서
  그런 기록에는 버튼이 없어요. 문서는 루나의 문서\Luna 폴더에 있는 것만 되돌릴 수 있어요.
- 루나는 기록에서 자기 최근 행동을 보고, 무엇을 했냐고 물으면 없는 말을 지어내지 않아요.
- Unreal 되돌리기는 모의 환경에서만 확인했어요. 실제 UE 4.25에서는 아직 시험해 봐야 해요.
- 문서 텍스트는 사용자에게 필요한 언어로 써요(기본은 대화 언어).

AI가 캐릭터를 조종하는 방법
모델의 답변은 그냥 텍스트가 아니라 시나리오예요: 글 속에 명령이 바로 들어 있는 말이에요.
예: [happy] 안녕! [nod] 만나서 반가워. [look:up] 잠깐 생각해 볼게… [look:user] [tilt] 너는 어때?
명령은 글에 적힌 바로 그 말의 순간에 아바타에서 실행돼요:
  감정  [neutral] [happy] [sad] [angry] [surprised] [shy] [love] [confused] [excited]
  제스처 [nod] 끄덕임, [shake] 부정, [tilt] 고개 갸웃, [wink] 윙크, [lean] 앞으로 몸 기울이기
          [shrug] 어깨 으쓱, [bow] 인사, [giggle] 킥킥 웃기, [puff] 볼 부풀리기(모델에 그런
          파라미터가 있다면), [blush] 홍조(있다면), [sigh] 한숨, [bounce] 깡충 뛰기
  시선  [look:user|left|right|up|down|away]
서버는 알 수 없는 명령을 버리고(app.py, parse_script), 채팅과 음성에는
깨끗한 텍스트만 가요. 시나리오와 별개로 아바타는 스스로 살아 있어요: 숨 쉬고, 눈을 깜박이고, 눈을 작게 움직이고,
말하는 중에 가끔 시선을 돌리고, 답을 기다리는 동안 "생각하고"(위를 봐요), 마이크가 열려 있으면
고개를 갸웃하고 끄덕이며 들어요.
생동감: 머리는 사인파로 흔들리지 않고, 몇 초마다 새 자세를 고르고
부드럽게 그쪽으로 옮겨 가요. 시선이 바뀔 때 눈을 깜박이고 가끔은 두 번 깜박여요. 강세가 있는
음절에서는 머리와 눈썹이 살짝 끄덕이고, 입 모양은 모음에 따라 달라지고(목소리의 스펙트럼으로),
말이 멈춘 사이에는 스스로 두리번거리고, 고개를 갸웃하고, 미소 지어요. 설정의
"움직임 생동감" 슬라이더가 이 모든 것을 더 세게 또는 더 약하게 해 줘요.
설정의 "시선이 커서를 따라감" 체크는 AI의 시선 조종을
끄는 스위치예요(기본은 꺼짐).

루나: 성격과 기억
성격, 만든 사람의 역할, 그리고 루나가 몸으로 할 수 있는 일의 목록은
settings.json(personality)에 있어요. 글로 고치고, 다시 시작해야 해요.
장기 기억은 앱 옆의 memory.json 파일이에요(.gitignore에 들어 있어요):
  "만든 사람에 대해"와 "자신에 대해"는 짧은 사실의 목록이에요. 메시지 3개마다 모델이
  백그라운드에서 최근 대화 조각을 다시 읽고 목록을 갱신해요(중복은 합치고,
  낡은 건 지우고, 최대 30개 항목). 마지막 12개 발언과 만난 횟수도
  저장되어서, 다시 시작한 뒤에도 루나가 대화를 기억하고
  얼마나 대화하지 않았는지 알아요. "새 대화 (기억은 유지)"는 기억을 건드리지 않고, "루나의 기억 지우기"
  (설정)는 모두 지워요. 파일을 열어서 직접 고쳐도 돼요.
먼저 말 걸기: 실행하면 루나가 먼저 인사해요(기억과 떨어져 있던 시간을 반영해서). 그리고
1분 30초~3분 동안 조용하면 스스로 말을 걸어요. 사용자가 입력하거나 말하는 동안에는 끼어들지 않고,
사용자의 답 없이는 연속 두 번까지만 말해요. 설정의 체크로 끌 수 있어요.
브라우저는 페이지를 처음 클릭하기 전까지 소리를 허용하지 않을 수 있어요. 그럴 때 인사는
목소리 없이 글과 제스처로 나와요.
기분: 숫자 두 개, 기쁨과 에너지가 memory.json에 저장돼요. 루나 자신의
답변 속 감정에 따라 움직여요(슬퍼하면 기쁨이 떨어지고, 기뻐하면 올라가요). 스스로
평소 수준으로 돌아가고(기쁨은 약 6시간, 에너지는 약 3시간), 하루 넘게 떨어져 있으면
조금 가라앉아요("보고 싶었어"). 기분은 프롬프트로 루나에게 전달되고 아바타도 바꿔요: 가만히 있을 때의 옅은
미소나 찌푸림, 에너지가 낮을 때 늘어진 머리와 줄어든 움직임.
되돌아보기: 실행할 때, 그리고 긴 대화에서는 메시지 8개마다 마지막 대화를 떠올려서
일기에 기록(2~3문장)과 다음에 묻고 싶은
질문을 써요. 마지막 세 개의 기록과 질문이 프롬프트에 들어가요.
기록, 기분, 질문은 성장 페이지에서 볼 수 있어요.
스트리밍 응답: 서버가 모델의 답을 쓰는 대로 읽어서
문장 단위로 잘라요. 나머지가 아직 쓰이는 동안 첫 문장부터 목소리가 나오기 시작해요
(다음 문장은 미리 음성으로 만들어 둬요).
서버는 답을 한 줄씩(한 줄에 JSON 하나) 내보내고, 페이지가 문장을 차례로 재생해요.
끊기: 루나를 클릭하거나 Esc 키를 누르면 말과 답변이 중단돼요(이미
말한 부분은 기록에 남아요). 설정의 "음성으로 루나의 말을 끊기" 체크가
("버튼 없이 대화"와 함께) 루나가 말하는 동안에도
마이크를 켜 두어요: 사용자가 말하기 시작하면 루나가 입을 다물어요.
헤드폰이 필요해요. 없으면 마이크가 루나 자신의 소리를 들어요.
듣는 동안의 반응: 사용자가 말하는 동안 따뜻한 말에는 미소 짓고 무거운 말에는 시무룩해져요
(러시아어, 영어, 일본어, 한국어: 단순한 단어 사전이에요). 사용자가 입력을 시작하면
입력란을 흘끗 봐요.
카메라(설정의 체크, 실행할 때마다 꺼져 있어요): 브라우저가 얼굴을 인식해요
(MediaPipe, 사용자의 컴퓨터에서. 라이브러리와 얼굴 모델은 켤 때 CDN에서
내려받아요). 영상은 어디로도 전송되지 않고 녹화되지 않아요. AI는 이미지를
받지 않고, "옆에 있다 / 웃고 있다 / 떠났다"만 알아요. 루나는 사용자의 얼굴이 있는 쪽을 봐요. 웃으면
같이 웃고, 놀라면 같이 놀라요. 사용자가 4초 넘게 없으면
먼저 말 걸기를 멈추고 시선으로 "찾아보고", 30초 이상 지나 돌아오면 먼저
인사해요. 화면 구석에 빨간 점이 있는 작은 창이 보여요.
생생한 대화(설정의 체크, 기본은 꺼짐): 루나가 방 안에 있는 사람처럼 행동해요. 조용할 때
더 자주 말을 걸고(1분 30초~3분 대신 10~35초마다) 다양하게 해요:
생각, 관찰, 가벼운 질문, 한숨, 흥얼거림, 농담, 지난 주제로 돌아가기.
가끔은 말없이 제스처만 해요(고개 갸웃, 한숨, 시선 돌리기). 물었는데 답이 없으면
질문을 반복하지 않고(다음 말은 다른 주제로 해요), 답 없는 발언이 있을 때마다
간격이 길어져요(최대 약 4분). 하지만 영영 입을 닫지는 않아요.
꺼져 있으면: 모든 게 예전과 같아요.

동작(에이전트 1단계): 루나가 부탁에 따라 사이트, 프로그램, 게임, 파일, 폴더를 열어요.
세 가지 방법이 있어요. (1) actions.json의 항목(빠르고 사용자 것이에요). (2) 컴퓨터에서 찾기: "과제
열어 줘", "Cyberpunk 실행해 줘", "내 Unreal 프로젝트 열어 줘". 앱이 직접 찾고(시작 메뉴,
바탕 화면, 문서/다운로드/비디오/음악/사진, Steam 게임), 찾은 것을 보여 주고
"이거 맞아요?"라고 물어요. (3) Google 검색: "구글에서 날씨 검색해 줘", "검색할까요…?" 카드가 떠요.
보안: 파일 목록은 AI로 가지 않아요(AI는 찾는 대상의 이름만 말하고, 찾는 건 앱이 해요).
카드를 사용자가 누르기 전에는 아무것도 열리지 않아요. 부탁 없이 스스로 아무것도 열지 않고,
다운로드의 스크립트와 exe는 아예 찾지 않아요. 설정에 "동작" 스위치가 있어요.
직접 추가는 actions.json에: kind가 url(사이트) 또는 app(프로그램, steam://rungameid/ID).
마우스와 키보드(2단계, Electron 창에서만, 설정 "루나가 마우스와
키보드를 사용할 수 있게 하기", 기본은 꺼짐): "메모장 열고 장보기 목록 써 줘". 루나가 보여 주는
카드 "루나가 이걸 할게요: …? [시작]"를 사용자가 누른 뒤에만 단계별로: 화면 스냅샷
-> 모델이 행동 하나를 고름 -> 실행 -> 새 스냅샷. 보호: (1) 작업마다
«시작»을 누른 뒤에만 움직여요. (2) 화면 위쪽에 빨간 «중지» 패널이 뜨고, 단축키는 Ctrl+Alt+K이며, 사용자가 마우스를 조금이라도
움직이면 즉시 멈춰요. (3) 전송, 결제, 삭제는 매번
따로 «예»라고 확인해요. (4) 서버 쪽 한도: 30단계, 40번의 동작, 6분. (5) 허용되는 것은
클릭, 더블클릭, 오른쪽 클릭, 텍스트 입력, 스크롤, 대기, 그리고 짧은 키 목록뿐이에요(
Windows 키, Alt+F4, 기능 키는 제외). 명령은 실행할 수 없어요. (6) 비밀번호와
결제 정보는 입력할 수 없고, 로그인이나 캡차가 나오면 멈춰요. 작업 중에는
화면 스냅샷이 Z.ai로 전송돼요(화질 1600x1000). 속도가 느리고 실수할 수도 있어요.
테스트: tests/ (실행: run-tests.bat 또는 `py tests/run_all.py`), 「테스트」 항목을 보세요. 설치: install.bat, tools\install.py. 성격과 기억: character.py. 기록 파일: audit.py, web/journal.js. 프로젝트 만들기: projects.py. 코드 수정: codeedit.py (web/app.js, index.html의 diff 창).
파일: control.py (작업과 한도), inputctl.py (ctypes로 마우스/키보드), agent.py.

Unreal Engine (3단계예요. 루나의 능력이라 따로 설정할 것은 없고, 모든 작업은 여전히 사용자의 «실행» 승인을 기다려요).
편집기가 열려 있을 때 «сделай куб»라고 말하면, 루나는 코드를 쓰지 않고 정해진 목록에서 작업 하나를 골라 이름을 불러요(태그 [ue:...]):
spawn <cube|sphere|cylinder|cone|plane|pointlight|
spotlight|directionallight> [x y z [배율]], move dx dy dz, rotate pitch yaw roll, scale k,
delete (spawn을 뺀 모든 작업은 편집기에서 선택된 것에 적용돼요. 좌표 없이 spawn하면
편집기 카메라 앞에 오브젝트를 놓고, 그 오브젝트는 선택된 채로 남아요). 서버가 숫자를 검증하고
미리 만든 템플릿에 끼워 넣어요. 작업 전에는 매번 «실행할까요?» 카드가 뜨고, 삭제는 따로 묻고
(«조심하세요»), 1분에 20번, 선택한 오브젝트는 20개까지만 가능해요. 모든 수정은 하나의
트랜잭션으로 처리돼서 Unreal에서 Ctrl+Z로 되돌릴 수 있어요.
Unreal 설정(한 번만): Edit > Plugins > «Python Editor Script Plugin» (4.25에서는
Experimental) > 재시작, 그다음 Edit > Project Settings > Plugins > Python >
«Enable Remote Execution». 연결은 Epic의 프로토콜로 이루어져요(UDP 멀티캐스트 239.0.0.1:6766,

무엇을 언제 알게 되었고 무엇을 잊었는지가 나와요. 데이터는 앱 토큰으로 읽고, 밖으로 내보내지 않아요.
떠올리기와 잊기: 프롬프트에는 30개의 사실을 전부 넣지 않고, 대화에 가장 알맞은

오래 건드리지 않은 사실부터 잊어요(그 기록은 성장 페이지에 보여요).
기억은 모델이 JSON을 얼마나 정확하게 만들어 주느냐에 달려 있어요. 업데이트에

바탕 화면 창 (Electron)
실행: start-desktop.bat (처음 실행할 때 Electron을 알아서 설치해요. Node.js와 Python이 필요해요).
- 루나는 배경 없이 모든 창 위에 나타나요. 클릭은 빈 곳을 통과하고
  루나 본인과 인터페이스에서만 잡혀요. 루나를 마우스로 끌어 옮길 수 있고 자리는 기억돼요.
- «화면 보기»는 설정에서 켜요(설정 탭의 «시각» 그룹).
  Ctrl+Alt+L: 바로 보기를 멈춤, Ctrl+Alt+Q: 루나 종료.
- 트레이: 루나는 Windows 알림 영역에 아이콘(초승달)이 있어요. 아이콘을 클릭하거나 Ctrl+Alt+H를 누르면 루나가 숨고
  다시 나타나요. 오른쪽 버튼: «숨기기/보이기», «종료». 숨어 있어도 계속 작동하고(기억, 오늘의 날짜)
  사용자가 보고 있지 않을 때는 먼저 말하지 않아요.
- 화면 보기는 실행할 때마다 꺼져 있고, 설정에서 확인 창을 거쳐 켜요.
  켜져 있고 «생생한 대화»도 켜져 있는 동안 몇 분에 한 번 루나가 화면을
  봐요(스냅샷은 작게 줄여서 무료 모델 Z.ai glm-4.6v-flash로 보내고 어디에도
  저장하지 않아요). 가끔 본 것을 이야기하고, 할 말이 없으면 조용히 있어요.
  타이머로 보는 것이 아니에요. 10초마다 무료 로컬 검사(맨 위 창의
  이름과 화면이 얼마나 바뀌었는지, 이미지는 보내지 않아요)로 볼 가치가 있는지 판단해요.
  다른 창으로 바꾸고 화면이 안정되었을 때, 또는 오랫동안
  화면이 크게 바뀌었을 때예요. 정지된 화면은 비용이 전혀 들지 않아요.
- 화면에 대해 직접 물어보면(«видишь?», «посмотри», «что я делаю», «оцени»),
  스크린샷을 바로 찍어서 곧장 답변에 쓰여요(«화면 보기»가 켜져 있을 때예요.
  꺼져 있으면 루나가 솔직하게 말해 줘요). 기준값은 app.js(pollScreen)에서 조절할 수 있어요. 화면에 자기 자신이
  보일 수도 있는데 정상이에요. 꺼짐 = 스냅샷을 아예 찍지 않아요.
- 제한: Electron에서는 음성 인식(마이크)이 작동하지 않으니, 창에서는 글로 쓰세요.
  음성 입력은 브라우저 버전(start.bat)에서만 쓸 수 있어요.
- 이 모드의 음성은 이전과 같아요.

  상업적 스트리밍을 금지해요).

  인터넷에 공개하지 마세요. 코드는 AI의 도움으로 준비했으니 발표하기 전에 직접 살펴보세요.
