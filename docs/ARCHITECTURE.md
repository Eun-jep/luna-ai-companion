# Архитектура

```
браузер / Electron ──HTTP 127.0.0.1:47615──► app.py (Handler)
   index.html + web/*.js                         │
   Pixi + Live2D + MediaPipe                     ├─ chat_turn(): один ход разговора (потоком, NDJSON)
                                                 ├─ system_prompt(): собирает промпт из памяти, настроения, режимов
                                                 ├─ generate/generate_stream(): нейросеть через luna.core.providers
                                                 └─ маршруты /act, /tts, /code/read, /doc/read … (каждое действие — по токену-плашке)
```

## Пакет `luna/`

| Пакет | Назначение | Правило |
|---|---|---|
| `luna/paths.py` | `DATA_DIR` (личные данные вне проекта), `ROOT`, `migrate()` | в тестах — всегда временная папка |
| `luna/security.py` | Host/Origin, токен, CSP/заголовки, `neutralize()` | чистые функции, без зависимостей |
| `luna/core/` | `character` (память, настроение, дневник), `memory_store` (поиск по смыслу), `providers`, `script` (сценарий ответа и чистые текстовые помощники), `models`, `voice`, `convo`, `lexicon`, `audit` | не знает о HTTP |
| `luna/skills/` | то, что считает программа, а не модель: `dates`, `exact`, `lists`, `habits`, `reminders`, `stream`… | у каждого навыка — разбор фразы на 4 языках и точный ответ |
| `luna/senses/` | `hearing`, `media`, `songid` | только локальная обработка |
| `luna/hands/` | `docfiles`, `codeedit`, `projects`, `runner`, `office`, `control`, `netsearch`… | всё, что меняет мир, — только после плашки и нажатия пользователя |
| `luna/dev/` | `devtools`, `engines`, `*_bridge`, `sqlrun`, `gitdiff`, `codescan`… | только чтение, пока нет плашки |

## Главные идеи

1. **Программа решает, модель предлагает.** Модель пишет команды вида `[open:…]`, `[run:…]`; сервер превращает их в плашку с токеном. Действие выполняется только после нажатия
   пользователем и только по токену, выданному именно для этой плашки (`agent.take`, `*.take`). Токены одноразовые и с TTL.
2. **Заражение (taint).** Если в ходе был текст «снаружи» (интернет, документ, файл с кодом, буфер обмена, SQL, diff), `chat_turn` считает ход `tainted`:
   ничего не открывается и не запускается само. Клиент ставит `webRound` после каждого такого чтения (`web/app.js`).
3. **Точные вычисления — в программе.** Даты, проценты, длинные числа, таблицы считает код (`luna/skills`), модель лишь формулирует ответ.
4. **Память.** `memory.json` (факты о пользователе и о ней, дневник, настроение) с бэкапами; `character.recall()` выбирает факты по совпадению слов, форме слова и,
   если задан `"embeddings": "ollama:nomic-embed-text"` в `settings.json`, по смыслу (локальные эмбеддинги, кэш в SQLite).
5. **Данные пользователя отдельно от кода** (`luna/paths.py`).

## Почему `app.py` всё ещё большой (~1950 строк)

Чат-движок (`chat_turn`) и `Handler` делят изменяемое состояние уровня модуля (`AGENT`, `WORK`, `CONTROL`, `PRESENCE`, `LAST_LANG`…) и подменяются в тестах
(`app.generate_stream`, `app.run_action` …). Разрезать их без перехода на объект `Session`/`App` значит сломать это поведение. Вынесено всё, что не имеет состояния
(`luna/core/script.py`, `luna/core/models.py`). Следующий шаг: ввести класс `Session` с этим состоянием, затем разнести маршруты по модулям.
