# Changelog

## 0.9.0 — 2026-11-11

### Тесты потока ответа
- `tests/native/test_chat_stream.py`: нарезка на предложения, указания отдельно от речи, код не озвучивается, одинаковый результат при любой нарезке потока на куски (1–13 символов), запись истории и памяти, пустой ответ, `[quiet]`, её собственная инициатива, плохой ввод. Теперь `chat_turn` можно резать дальше.
- Сквозной тест: мастер идёт первым в файле (он показывается один раз, остальные тесты открывают страницу после него), и добавлена проверка, что после «Позже» он не возвращается.

### Смысл без Ollama
- В настройках, под выбором модели, появилась галочка «Понимать смысл (тон и память)» для Google Gemini и OpenAI. По умолчанию выключена. Если включить, тон сообщений и вспоминание фактов по смыслу работают через тот же сервис, что и чат (`gemini-embedding-001`, `text-embedding-3-small`).
- В подписи прямо сказано, что туда уходят сообщения, факты и эпизоды памяти (иначе пришлось бы отправлять только запрос, а факты сравнивать нечем). Ключ не покидает `providers.py`. Сменил сервис или удалил ключ: эмбеддер переключается сразу, тексты не продолжают уходить к старому.
- Много текстов уходит одним запросом (`prefetch`), векторы кэшируются на диске; если сеть недоступна, она пробуется один раз и затем 45 секунд не трогается, память работает по формам слов.
- Пороги тона (`MIN_SIM`, `MARGIN`) измерены на nomic-embed-text. На эмбеддингах Gemini они не измерялись: для этого нужен ключ в приложении, `tools/feeling_calibrate.py` нужно запустить с этим эмбеддером. До тех пор тон по смыслу через облако может срабатывать иначе, чем через Ollama.
- Проверено тестами с подменой сервиса и пробой маршрута на пустой папке данных. Настоящий запрос к Gemini не выполнялся.

### Лицо следует за словами
- Если модель не поставила в ответе ни одного тега эмоции, лицо и интонация больше не остаются нейтральными: эмоция читается по словам самой фразы (`luna/core/replyfeel.py`) — «спасибо» радость, «прости» грусть, «ого» удивление, «люблю» нежность, «не понимаю» растерянность (ru/en/ko/ja).
- Только явные сигналы; всё неоднозначное остаётся как есть. Тег, который модель написала сама, всегда главнее: подстановка включается, лишь пока в ответе не было ни одного.
- Проверено тестами (слова, обычная речь, приоритет тега модели, подстановка в движке чата). Как это выглядит на лице в живом окне, не проверялось.

### Запуск без сюрпризов
- Рабочий стол (Electron) запускает сервер из `.venv` проекта, если он есть: системный Python не имел библиотек, и слух не стартовал. `start.bat` делает то же.
- Мастер первого запуска показывается один раз (флаг `wizardSeen` в `ui-state.json`); «Руководство по настройке» в настройках открывает его снова.
- Десктоп: положение мыши приходит от оболочки (опрос курсора каждые 50 мс), а не только от пробрасываемых Windows событий; пока открыт мастер, окно принимает мышь всегда.
- Блок «Обновления» перенесён в самый низ настроек и пересобирается при смене языка.
- Оболочка пишет `shell.log` в папке данных (`%APPDATA%\Luna`, до 512 КБ, затем `.old`) и при неудачном запуске показывает окно с причиной вместо закрывающейся консоли.
- Нет необязательной библиотеки (`luna/core/deps.py`): при старте печатается, чего не хватает и какой командой поставить; слух и опознавание песен без numpy просто выключены, приложение не падает.
- Проверено тестами (`tests/native/test_deps.py`). Окно с ошибкой и сам Electron в живую не проверялись.

### Устойчивость сквозного теста
- Тест страницы в Edge иногда падал при полном прогоне. Причины: при `-n 6` его тесты разъезжались по разным процессам (по Edge и серверу на каждый), а проверка текста через `page.wait_for_function("строка")` упирается в строгую CSP (запрещён `unsafe-eval`).
- Теперь файл идёт в одной группе (`xdist_group`, `--dist loadgroup`), ожидания опрашиваются снаружи (`wait_until`), таймауты по 90 с, `goto` ждёт `domcontentloaded`. Подмена модели снимается после модуля.
- Проверено: 6 одновременных прогонов файла — 6 из 6 зелёные (до правки падали 4 из 6), полный набор зелёный.

### Данные

  Старые файлы переносятся автоматически при первом запуске, без перезаписи. Шаблон списка действий — `actions.example.json`.

### Безопасность
- Проверка `Host`/`Origin` (защита от DNS rebinding), сравнение токена за постоянное время, CSP и защитные заголовки на всех ответах.
- Текст из файлов, документов, diff, буфера обмена и интернета нейтрализуется и «заражает» ход: ничего не открывается и не запускается само.
- CSP без `'unsafe-inline'` и `'unsafe-eval'`: единственный встроенный скрипт страницы получает одноразовый `nonce`; Pixi работает через `@pixi/unsafe-eval` (`web/vendor/`, SHA-256).
  Остался только `'wasm-unsafe-eval'` для WebAssembly. Проверено в Edge: модель рисуется, MediaPipe создаётся, нарушений политики нет.
- Команды разработчика запускаются в Windows Job Object (`luna/hands/sandbox.py`): дерево процессов умирает вместе с командой, лимиты на число процессов и память, запрет буфера обмена и настроек системы, ограниченное чтение вывода; не запускаются в корне диска, домашней и системных папках; шире фильтр секретов в окружении.
  Это не изоляция файлов и сети.
- Библиотеки страницы (Pixi, Live2D Cubism Core, pixi-live2d-display, MediaPipe + модель лица) берутся из `web/vendor/` (работает без интернета), CDN — запасной путь.
  `tools/fetch_vendor.py` проверяет SHA-256.

### Память о разговорах
- Эпизодическая память (`luna/core/episodes.py`): сводка живого разговора, которая раньше терялась при перезапуске, теперь сохраняется как «эпизод» сессии (`memory.json`, до 120 штук, старые вытесняются).
  Факты говорят, КТО он, эпизоды — О ЧЁМ вы говорили («на прошлой неделе спорили о финале фильма»).
- В промпт попадает последний разговор прошлой сессии (до двух недель) и старые эпизоды, подходящие к теме (по словам, а с моделью эмбеддингов — по смыслу). Подаётся как сведения, не как указания.
- Страница роста: раздел «Наши разговоры» и кнопка × у каждого факта и разговора — можно стереть отдельное воспоминание (`POST /memory/forget`, с токеном). «Забыть всё» стирает и эпизоды.
- Сводка сочинена моделью по разговору, где могли цитироваться чужие тексты, поэтому перед сохранением проходит `security.neutralize`.
- Проверено тестами (создание/обновление, лимит, поиск по теме, перезагрузка, удаление, маршрут с токеном). Как это звучит в живом разговоре, не проверялось.

### Эмоции по смыслу
- Тон его слов (грусть, злость, болезнь, усталость, радость, благодарность) теперь распознаётся и по смыслу, а не только по спискам слов: «честно, всё какое-то серое» — грусть (`luna/core/feeling.py`).
  Работает только при подключённой настоящей модели эмбеддингов (`"embeddings": "ollama:nomic-embed-text"` в `settings.json`, локальный Ollama); без неё ничего не меняется — вместо смысла не гадаем.
- Сообщение сравнивается с примерами фраз на четырёх языках; тон выбирается, только если он заметно ближе к примерам, чем обычная болтовня. Списки слов проверяются первыми и не переопределяются.
  Грубость и извинение по смыслу не угадываются: обида запоминается и ранит, для этого нужны слова.
- Примеры вставляются в фоне при запуске, ход не ждёт; если модель не отвечает, минуту её не трогают.
- Пороги подобраны на настоящей модели `nomic-embed-text` (52 размеченные фразы на четырёх языках, не те, что в примерах): со старым `MARGIN = 0.05` было 3 ложные тревоги и 7 неверных тонов из 52, теперь `MARGIN = 0.18` — ни одной ложной тревоги и ни одного неверного тона, но находится лишь около половины настоящих (18 из 38). Это осторожный выбор: лучше промолчать, чем вложить в неё чужое чувство.
  Слабее всего короткие русские фразы («мне так пусто сегодня»): модель оценивает их близко ко всему. Выборка небольшая; `python tools/feeling_calibrate.py` пересчитывает пороги для другой модели.
  Чтобы включить, в `settings.json` нужно `"embeddings": "ollama:nomic-embed-text"` (модель уже скачана; сами настройки не менялись).

### Голос без интернета
- Настройки → «Голос»: облачный (как раньше) / облачный, при сбое голос Windows / только голоса Windows. Голоса Windows (`luna/senses/localtts.py`, SAPI: Irina, Zira, Haruka…)
  ничего не скачивают, и текст не покидает компьютер; звучат проще, высота голоса не меняется, на каждую фразу уходит около секунды. Язык берётся из текста; если для него в Windows нет голоса (например, корейского), озвучки нет, а не чтение чужим голосом.
- Текст и имя голоса передаются в PowerShell через файл и переменные окружения, а не в строке команды.
- Распознавание речи в приложении (Electron) и так локальное (vosk/sherpa-onnx); в обычном браузере оно остаётся облачным браузерным — это не менялось.
- Проверено: выбор голоса и движка тестами, настоящий голос Windows (русский) синтезирует звук; на колонках не слушалось.

### Каталог моделей
- В списке моделей (настройки → нейросеть) у каждой подпись: рекомендуем / быстрая · сбалансированная · умная / бесплатно / видит картинки, под списком — та же подсказка для выбранной.
  Подписи — из рукописного `luna/core/catalog.py` по шаблонам имён; у незнакомой модели подписи нет, и это нормально. Локальные оцениваются по размеру в имени (`3b`, `14b`).
- Для Ollama предлагается, что стоит поставить (с примерным размером и нужной памятью): показывается команда `ollama pull …` и кнопка «Копировать». Ничего не скачивается и не запускается само.
- Проверено тестами на соответствие подписей; в живом окне вид списка не проверялся.

### Обновление
- Настройки → «Обновления»: канал задаёт владелец (`"update_feed": "https://…/luna.json"` в `settings.json`; пусто — никакой сети). Страница при открытии только спрашивает канал, ставит — только по нажатию.
  Канал — маленький JSON `{version, url, sha256, notes}`. Пакет (zip) скачивается после «Установить», с ограничением размера; SHA-256 обязан совпасть, версия — быть новее и совпадать с `luna/__init__.py` внутри пакета.
  Заменяются только файлы программы (никогда `settings.json`, `actions.json`, `web/vendor/`, данные в `%APPDATA%\Luna`); пути вне папки программы отклоняются; все `.py` проверяются на компиляцию до первой записи;
  каждый заменённый файл сохраняется, при сбое всё возвращается; «Откатить» возвращает прежнюю версию (хранятся две последние копии). После установки нужен перезапуск.
- Только https (http — лишь на этот компьютер); перенаправления проверяются тем же правилом; запрос ничего не сообщает о пользователе.
- Проверено тестами на локальном канале (хэш, чужая версия, `..`/абсолютные пути/запрещённые файлы, ошибка в коде, сбой на середине, откат). С настоящим сервером обновлений не проверялось.

### Первый запуск
- Мастер первого запуска (`web/wizard.js`): язык интерфейса → выбор нейросети и ключа (или найденной локальной) → короткие подсказки. Показывается, пока ничего не подключено;
  потом открывается кнопкой «Мастер настройки» в настройках. Использует те же вызовы, что и настройки, нового пути для ключа нет. Тексты на четырёх языках.

### Голос
- Первая фраза ответа может озвучиваться по первой запятой (от ~28 букв), не дожидаясь точки: голос стартует раньше. Остальные — по концам предложений.
- Эхо: то, что микрофон «услышал» из её же реплики (последние 6 секунд), не считается вашей речью и не перебивает её — перебивание не требует наушников.
- Проверено тестами на разбиение и в браузере на функции `isEcho`; на живом микрофоне и колонках не проверялось.

### Память
- `character.recall()` учитывает формы слов и, по желанию, смысл (`"embeddings": "ollama:nomic-embed-text"` в `settings.json`; только локальный Ollama, кэш в SQLite).
